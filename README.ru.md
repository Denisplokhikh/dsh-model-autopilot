# Model Autopilot — плагин для DSH

Панель в левой боковой панели, которая переключает модель агента на каждом шаге: **Лёгкий** для обычных ходов, **Средний** для точечной работы с кодом и **Сложный** для многошаговой работы или после повторяющихся ошибок инструментов.

`MIT` · `без сборки` · `без runtime-зависимостей` · `без телеметрии` · `без сторонних API-ключей`

[English version](README.md)

## Что он делает

Сессия работы с кодом неоднородна по сложности. Одни шаги открывают файл, запускают тесты или отвечают на вопрос; другие планируют миграцию или разбирают падающий трейс. Гонять самую большую модель на всё — переплата, а маленькую на архитектуру — ложная экономия. Model Autopilot классифицирует каждое входящее сообщение пользователя и выбирает модель для следующего шага агента из настроенных уровней.

| Уровень | Id | Когда выбирается |
| --- | --- | --- |
| Лёгкий | `fast` | Обычные ходы, короткие вопросы, небольшие справки. |
| Средний | `coder` | Точечные правки кода, отладка, ревью. |
| Сложный | `heavy` | Архитектура, миграции, широкий рефакторинг и циклы ошибок. |

Ничего не зашито в код, и до включения плагин ничего не делает.

### Ноль сторонних API-ключей

Плагин использует только тех провайдеров и те модели, которые вы уже настроили в DeepSeek Harness (**Настройки → Модели**). Нет зашитых id моделей, внешнего сервиса классификации, телеметрии и дополнительного аккаунта. В режиме `local` (по умолчанию) классификация не выходит за пределы процесса DSH; необязательный режим `fast` делает один небольшой запрос через вашу же модель быстрого уровня (см. ниже).

## Требования

- DSH Desktop или DSH Web с профилем — 0.2.x (собрано и проверено на `0.2.2-rc.1`). В профиле должны быть стандартные сервисы `llm`, `agentDefaultModel` и `configEditor` — в обычных desktop- и web-профилях они есть.
- Хотя бы один провайдер в **Настройки → Модели**.
- Node.js 20 или новее — для офлайн-самопроверки из репозитория (`"engines"` в [package.json](package.json)). Сам плагин исполняет DSH.

## Установка

Это bundle-плагин DSH: `dsh.bundle.patch` в [package.json](package.json) указывает на [cordis.patch.yml](cordis.patch.yml), который вставляет в профиль одну строку `model-autopilot` — выключенную по умолчанию.

### A. Из каталога плагинов (Discover)

В репозитории есть [index.json](index.json) — запись каталога, закреплённая за релизным коммитом.

1. Включите необязательный bundle `@deepseek-ai/dsh-experimental-plugin-market-bundle` в **Настройки → Плагины** (он поставляется с DSH и выключен по умолчанию) и откройте вкладку **Discover**.
2. Добавьте ссылку на каталог:
   ```
   https://raw.githubusercontent.com/Denisplokhikh/dsh-model-autopilot/main/index.json
   ```
3. Найдите **Autopilot** и установите его.

### B. Из клона или локальной копии

```bash
git clone https://github.com/Denisplokhikh/dsh-model-autopilot.git
```

Затем попросите агента DSH установить bundle из этого абсолютного каталога (`plugin_manager` → `install_bundle`). Пункт в боковой панели появится после перезагрузки веб-клиента.

### C. Вручную через зависимость профиля

Для профиля, который вы ведёте руками, добавьте пакет в зависимости профиля и установите его:

```json
{
  "dependencies": {
    "dsh-model-autopilot": "github:Denisplokhikh/dsh-model-autopilot"
  }
}
```

Патч bundle вставит строку в Cordis-патч профиля. Задайте её конфиг по разделу [Конфигурация](#конфигурация) и `enabled: true`, когда автопилот должен работать. Если строки нет, скопируйте блок `insert` из [cordis.patch.yml](cordis.patch.yml) в патч профиля. То, как профиль применяет патчи, — сторона DSH; смотрите её документацию. Плагин никогда не правит `cordis.patch.yml` во время работы: панель пишет через редактор конфига профиля.

После любого способа установки откройте **Автопилот** в левой боковой панели, настройте плагин и включите его. Если пункта в боковой панели нет, перезагрузите веб-клиент.

## Первый запуск

1. Откройте **Автопилот** в левой боковой панели.
2. В блоке **Уровни** оставьте уровень пустым или выберите для него провайдера и модель. Пустой уровень наследует модель по умолчанию из развёртывания и выводит своё усилие рассуждения (см. [Автоопределение уровней](#автоопределение-уровней)); строка под выбором показывает фактический маршрут и его источник.
3. В блоке **Классификатор** оставьте **Локальные эвристики** для мгновенного офлайн-пути или выберите **Быстрая модель моего провайдера**, чтобы классификацию уточняла ваша же модель быстрого уровня. Поле **Таймаут классификатора, мс** появляется только в режиме быстрой модели.
4. Задайте **Ошибок инструментов до переключения на сложный**, если значение по умолчанию `2` не подходит.
5. Сохраните, затем включите. Политика действует со следующего шага.

## Панель

Панель (заголовок **Автопилот моделей**, пункт в боковой панели **Автопилот**) редактирует тот же блок `config`, что лежит в патче профиля, и показывает не только сырые настройки, но и то, что реально будет выбрано:

- **Состояние** — включён или выключен (**Включён**/**Выключен**), переключатель «Включить/Выключить» и **Модель по умолчанию для новых сессий**.
- **Уровни** — **Лёгкий**, **Средний**, **Сложный**; для каждого выбираются провайдер и модель, сгруппированные по провайдеру. Под каждым выбором показан фактический маршрут `провайдер / модель · усилие — источник`, где источник — **задан вручную**, **авто от модели по умолчанию**, **модель по умолчанию (без уровней рассуждения)** или **пока недоступно**.
- **Классификатор** — **Локальные эвристики** или **Быстрая модель моего провайдера**, а в режиме быстрой модели ещё и **Таймаут классификатора, мс** (200–10000).
- **Ошибок инструментов до переключения на сложный** — порог эскалации (0–20).
- **Последние решения** — уровень, провайдер/модель (с усилием рассуждения, если оно есть), причина (**по запросу**, **после ошибок**, **по быстрой модели**), балл классификатора и время.

## Как маршрутизируется шаг

```
новое сообщение пользователя
      │
      ▼
локальный балл classifier.js ──(classifier: fast, сообщение ≥ 12 символов)──▶ один небольшой запрос через llm.stream
      │                                                               │ таймаут / ошибка / неразборчиво → локальный вердикт
      ▼                                                               ▼
выбор уровня (fast | coder | heavy) ──▶ проверка ──▶ agent.model.select() ──▶ следующий неподготовленный шаг
      ▲
результаты инструментов ──▶ подряд ошибок ≥ escalateAfterErrors ──▶ heavy
```

- **Сначала локальные эвристики.** [classifier.js](classifier.js) — чистый и синхронный: он оценивает намерение, масштаб, следы ошибок, структуру кода, признаки плана и длину, а «бытовые» сигналы учитывает только если больше ничего не сработало. На выходе — уровень, балл и сигналы, которые его дали. Без сети, без лишней задержки.
- **Маршрут меняют только ваши сообщения.** Host классифицирует сообщения из inbox с источником `user`. Вставленный контекст — напоминания рантайма, уведомления о смене модели, результаты сабагентов, сообщения плагинов — игнорируется: переключаться на напоминание было бы шумом.
- **Эскалация.** Host считает подряд идущие результаты инструментов с `isError` в рамках сессии. На значении `escalateAfterErrors` (по умолчанию `2`, `0` отключает эскалацию) он выбирает **Сложный** уровень (`heavy`) для следующего шага. Успешный вызов редактирования или оболочки сбрасывает счётчик, так что эскалация — не постоянное состояние; дальнейшие сообщения снова идут по классификатору.
- **Проверка цели.** Перед выбором host проверяет, что провайдер зарегистрирован в сервисе `llm` и что метаданные модели разрешаются (не дольше 4 секунд). Неизвестный провайдер или недоступная модель пропускаются, шаг агента при этом не ломается; усилие рассуждения, которое модель не объявляет, отбрасывается, а не приводит к ошибке выбора.
- **Выбор модели.** Host вызывает `agent.model.select()` для следующего неподготовленного шага; если агент уже ровно на целевой модели, вызов пропускается. Смена записывается в сессию как обычная смена модели.
- **Горячий путь.** Модель шага фиксируется до начала шага. Поэтому шаг, вызванный сообщением, решают локальные эвристики: они отрабатывают синхронно при вставке сообщения, по кэшу маршрутов, прогретому при загрузке и после каждого сохранения. (Отложить выбор на более поздний шаг может только самое первое сообщение после холодного старта, пока не разрешились метаданные модели.) Необязательный классификатор на быстрой модели, даже если ответит быстро, может изменить только шаг, который ещё не подготовлен, — на практике более поздний. Он улучшает классификацию, но не меняет задним числом шаг, который её вызвал.

### Автоопределение уровней

Оставьте провайдера и модель уровня пустыми — уровень наследует модель по умолчанию из развёртывания, то есть выбор по умолчанию в **Настройки → Модели**. Тогда уровни различаются усилием рассуждения: **Лёгкий** берёт минимальное усилие, которое объявляет модель, **Сложный** — максимальное, а **Средний** — усилие по умолчанию (или середину объявленного списка). Это и делает возможным запуск без настройки на модели по умолчанию, у которой есть несколько уровней рассуждения. Строка каждого уровня в панели показывает получившийся маршрут и помечает его как **авто от модели по умолчанию**.

Если модель по умолчанию не объявляет уровней рассуждения, все уровни сводятся к одному маршруту. Переключать нечего, поэтому плагин не выбирает модель; панель помечает такие уровни как **модель по умолчанию (без уровней рассуждения)**. В этом случае задайте разные модели вручную.

### Классификатор на быстрой модели (`classifier: fast`)

Когда классификатор переключён на быструю модель, host отправляет один крошечный запрос на сообщение пользователя (только для сообщений от 12 символов и не во время эскалации) через сервис `llm`, используя быстрый уровень вашего провайдера — или модель по умолчанию из развёртывания, если быстрый уровень её наследует. Запрос использует промпт из [classifier.js](classifier.js) и обрывается по `classifierTimeoutMs` (по умолчанию `1500`, допустимо 200–10000). Таймаут, ошибка провайдера или неразборчивый ответ оставляют локальный вердикт. Разобранный вердикт применяется, только если он отличается от локального, сообщение всё ещё последнее, а агент работает.

Поскольку модель шага фиксируется до его начала, вердикт может уточнить только ещё не подготовленный шаг. В журнале последних решений такие смены помечены как **по быстрой модели**.

## Конфигурация

Строка в Cordis-патче профиля. Настройки, сохранённые в панели, попадают в тот же блок, включая `classifier` и `classifierTimeoutMs`:

```yaml
- insert:
    - id: model-autopilot
      name: dsh-model-autopilot
      config:
        enabled: true
        escalateAfterErrors: 2
        classifier: local
        classifierTimeoutMs: 1500
        tiers:
          fast:
            provider: deepseek
            model: deepseek-chat
            reasoningEffort: ''
          coder:
            provider: deepseek
            model: deepseek-reasoner
            reasoningEffort: ''
          heavy:
            provider: deepseek
            model: deepseek-reasoner
            reasoningEffort: high
```

Id провайдера, модели и усилия выше — пример формы записи: используйте те id, которые объявляют ваши провайдеры в **Настройки → Модели**. `reasoningEffort: high` — пример id, который может предлагать модель; допустимы ровно те значения, которые модель сообщает.

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `enabled` | `false` | Главный выключатель. Пока `false`, плагин ничего не наблюдает и не меняет модель. |
| `escalateAfterErrors` | `2` | Сколько подряд идущих неудачных результатов инструментов в сессии должно быть до выбора Сложного уровня. Целое 0–20; `0` отключает эскалацию. |
| `classifier` | `"local"` | `"local"` — только эвристика, без запроса к модели. `"fast"` — один небольшой запрос классификации через модель быстрого уровня, локальный вердикт остаётся запасным. |
| `classifierTimeoutMs` | `1500` | Верхняя граница ожидания этого запроса, целое 200–10000. При таймауте используется локальный вердикт. Игнорируется при `classifier: local`. |
| `tiers.fast.provider` / `tiers.fast.model` | `""` | id провайдера и модели из **Настройки → Модели**. Задавайте оба или ни одного; пустая пара — автоопределение. |
| `tiers.fast.reasoningEffort` | `""` | Необязательный id усилия, которое объявляет модель. Выбор уровня в панели задаёт только провайдера и модель; усилие задаётся здесь. Пусто — усилие по умолчанию у модели, а для унаследованного уровня плагин выводит усилие из модели. |
| `tiers.coder.*` | — | Те же три ключа для Среднего уровня. |
| `tiers.heavy.*` | — | Те же три ключа для Сложного уровня. |

Провайдер и модель задаются всегда вместе: уровень, где заполнено одно и пусто другое, некорректен, и host отклонит сохранение. `reasoningEffort` необязателен везде, а в комплектном патче он записан пустой строкой.

## Если что-то не работает

| Симптом | Причина / что делать |
| --- | --- |
| Модель не меняется | Плагин выключен; все уровни пустые, а модель по умолчанию не объявляет уровней рассуждения; агент уже ровно на целевой модели (смена была бы пустой операцией); или заданный провайдер не зарегистрирован / его метаданные недоступны, и цель пропускается. Посмотрите журнал последних решений в панели. |
| Панель пишет, что моделей нет | В **Настройки → Модели** не настроен ни один провайдер, или в профиле нет сервиса `llm`. Настройте провайдера и перезагрузитесь. |
| Настроенный провайдер не появился в списке | Список берётся из сервиса `llm`; провайдер, который не инициализировался, в него не попадает. Проверьте **Настройки → Модели** и логи DSH. |
| Уровни показывают «модель по умолчанию (без уровней рассуждения)» | Модель по умолчанию не объявляет усилий рассуждения, поэтому все уровни сводятся к одному маршруту и переключения нет. Выберите разные пары провайдер/модель для уровней. |
| Сохранение в панели не удаётся | В профиле нет сервиса `configEditor` (сильно изменённый профиль). Задайте конфиг строки прямо в патче профиля. |
| Нет пункта в боковой панели | Пакет установлен, но веб-клиент не перезагружен. Перезагрузите клиент. |
| Сложные запросы всё равно уходят в Лёгкий | Классификация приблизительная, а в режиме быстрой модели вердикт может повлиять только на более поздний шаг. Посмотрите балл и сигналы в журнале решений; пока тестируете, поставьте одну и ту же модель в Лёгкий и Средний. |
| Самопроверка падает | Запустите `node verify.mjs .` из каталога пакета на Node.js 20+. Проверка офлайн: классификатор, маршруты host, автоопределение уровней, эскалация, путь быстрой модели, валидация настроек, регистрация клиента и локали. |

## Данные и приватность

- Никаких сторонних ключей, аккаунтов, телеметрии и зашитых адресов.
- В режиме `local` текст сообщения оценивается только в памяти; своего сетевого кода у плагина нет.
- В режиме `fast` один небольшой запрос классификации идёт через штатный сервис `llm` DSH к провайдеру и модели, выбранным для быстрого уровня. Это может быть ваша модель по умолчанию, то есть обычно тот же провайдер, которым сессия уже пользуется; нового адреса не появляется.
- Панель общается с host по аутентифицированным маршрутам того же источника `/api/model-autopilot/state` и `/api/model-autopilot/settings`. Настройки пишутся в профиль через `configEditor`; bundle никогда не переписывает `cordis.patch.yml` сам.

## Ограничения

- **Классификация — эвристическое приближение.** Локальный классификатор оценивает ключевые слова, структуру и длину, а не смысл запроса. Иногда он выберет не тот уровень; журнал последних решений показывает балл и сработавшие сигналы.
- **Модель шага нельзя сменить после его начала.** Модель фиксируется до шага, поэтому переключение нельзя отменить посреди шага. Классификатор на быстрой модели тоже не изменит шаг, который его вызвал: первый шаг решают локальные эвристики, а вердикт может уточнить только более поздний неподготовленный шаг.
- **Режим `fast` стоит дополнительного запроса.** Один небольшой вызов LLM на сообщение (от 12 символов) плюс ожидание до `classifierTimeoutMs` сверх обычного шага. Если точность того не стоит, оставьте **Локальные эвристики**.
- **Эскалация наивная.** Считается любой результат с `isError`, включая неудачи, которые не являются циклом (поиск без совпадений, намеренно падающая команда). Успешный вызов редактирования или оболочки сбрасывает счётчик.
- **Автоопределение зависит от модели по умолчанию.** Если она не объявляет усилий рассуждения, уровни сводятся к одному маршруту, и плагин не переключает модель. Для осмысленного разделения задайте модели вручную.
- **Смена модели может обнулить prompt-кеш провайдера**, поэтому переключение может стоить больше токенов на следующем запросе. Это цена маршрутизации; более дешёвый Лёгкий уровень обычно всё равно выигрывает на длинной сессии.
- **Пока плагин включён, он наблюдает за всеми живыми агентами профиля.** Классифицируются только сообщения с источником `user`; сообщения, вставленные другими плагинами, пропускаются. Политики на отдельную сессию пока нет.

## Архитектура

| Файл | Роль |
| --- | --- |
| [index.js](index.js) | Host-половина: регистрирует точные Fetch-маршруты `/api/model-autopilot/state` и `/api/model-autopilot/settings`, слушает `agent/inbox/inserted`, считает ошибки, выводит и проверяет цели уровней из модели по умолчанию, вызывает `agent.model.select()` и сохраняет конфиг через `configEditor`. |
| [classifier.js](classifier.js) | Чистая оценка без ввода-вывода: локальная эвристика, промпт для режима `fast` и разбор ответа. |
| [client.js](client.js) | Клиентская половина, загружаемая через `window.__ModuleLoader__`: панель в `sidebar.panellist` с фактическими маршрутами уровней и настройками классификатора, её стили и словари en/ru. |
| [cordis.patch.yml](cordis.patch.yml) | Патч bundle, вставляющий строку `model-autopilot`, выключенную по умолчанию. |
| [locale/en.json](locale/en.json), [locale/ru.json](locale/ru.json) | Название и описание панели для каталога и интерфейса. |
| [verify.mjs](verify.mjs) | Офлайн-функциональная самопроверка классификатора, обеих половин и контракта настроек. |
| [package.json](package.json) | Метаданные пакета, `dsh.bundle.patch`, `engines.node >= 20`, клиентская точка входа и exports. |

Ни сборки, ни runtime-зависимостей: обычный ESM, который загружает DSH. После изменений запускайте офлайн-проверку:

```bash
node verify.mjs .
```
