# Model Autopilot — плагин для DSH

**Одна панель в левой боковой панели — и каждый шаг агента идёт на модели, которая ему подходит:
дешёвая на обычных ходах, сильная для кода — на настоящей работе, тяжёлая — только когда агент
застрял.**

`DSH 0.2.x` · `MIT` · `без сборки` · `без зависимостей` · `без телеметрии`

[English version](README.md)

---

## Зачем

Агент для кода обычно работает на одной модели всю сессию. И это либо переплата, либо
недостаточная сила:

- **маленькая модель** нормально тянет «открой файл», «запусти тесты», «ответь на вопрос» — а это
  90% шагов;
- **большая модель** стоит своих денег только на шагах, которые решают: архитектура, сложный
  фикс, рефакторинг, реализация с нуля;
- когда агент **ходит по кругу из-за ошибок**, полезно позвать самую большую модель.

Model Autopilot делает это переключение сам, до начала шага, и показывает свои решения.

| Уровень | Когда выбирается | Обычно сюда ставят |
| --- | --- | --- |
| **fast** (быстрый) | любое новое сообщение, если не сработало ниже | маленькую и дешёвую |
| **coder** (для кода) | сообщение похоже на настоящую работу: архитектура, рефакторинг, фикс, перепись, оптимизация, реализация | сильную для кода |
| **heavy** (тяжёлый) | после заданного числа подряд идущих неудачных вызовов инструментов | самую большую |

Провайдера и модель для каждого уровня вы выбираете в панели. Ничего не зашито в код, и
**до включения плагин ничего не делает**.

## Скриншот

Панель живёт в левой боковой панели под именем **Автопилот**: переключатель, три выбора
уровня (списки берутся из настроенных провайдеров), порог ошибок и журнал последних решений.

## Требования

- DSH Desktop или DSH Web с профилем — 0.2.x (собрано и проверено на `0.2.2-rc.1`).
- Хотя бы один провайдер в **Настройки → Модели**: уровни выбираются из моделей, которые
  объявляют провайдеры.

## Установка

### A. Из каталога плагинов (Discover)

DSH умеет читать каталоги плагинов — JSON-индексы, которые пользователь добавляет по ссылке.
В этом репозитории такой индекс есть: `index.json`.

1. Включите bundle **plugin market** в профиле (он поставляется с DSH, но выключен по умолчанию)
   и откройте вкладку **Discover**.
2. Добавьте в настройках каталога ссылку на индекс:

   ```
   https://raw.githubusercontent.com/Denisplokhikh/dsh-model-autopilot/main/index.json
   ```

3. Найдите **Autopilot** и установите. Запись в индексе прибита к коммиту, поэтому вы получаете
   ровно тот код, который отмечен релизом.

### B. Из клона репозитория

```bash
git clone https://github.com/Denisplokhikh/dsh-model-autopilot.git
```

Затем попросите агента в DSH:

> Установи bundle плагина DSH из `C:\путь\к\dsh-model-autopilot`

Агент установит его через `plugin_manager` (`install_bundle`, абсолютный путь к папке). Запись в
боковой панели появится после перезагрузки веб-клиента.

### C. npm

Пока не опубликовано. Нужно на npm — откройте issue: метаданные пакета уже готовы.

## Первый запуск

1. Нажмите **Автопилот** в левой боковой панели.
2. Выберите провайдера и модель для нужных уровней. Пустой уровень пропускается, плагин берёт
   первый настроенный — поэтому можно начать с одного **fast**.
3. Задайте **Ошибок инструментов до переключения на тяжёлый** (по умолчанию `2`).
4. Нажмите **Сохранить**, затем **Включить**.

Маршрутизация действует со следующего шага. Само переключение записывается в сессию как обычная
смена модели, так что история остаётся читаемой.

## Как работает маршрутизация

```
сообщение ──▶ разбор текста ──▶ выбор уровня ──▶ agent.model.select() ──▶ следующий шаг
                    ▲                                  │
результаты ──▶ счётчик ошибок ──▶ heavy ──────────────┘
```

- **Разбор** читает текст только что вставленного сообщения и сверяет с эвристикой по ключевым
  словам (русский и английский). Совпало — `coder`, иначе `fast`.
- **Эскалация** считает подряд идущие результаты инструментов с `isError: true` в рамках сессии.
  На пороге сразу выбирается `heavy`, и новые сообщения остаются на `heavy`, пока счётчик не
  сбросится.
- **Сброс**: успешный изменяющий вызов инструмента (`edit`, `write`, `apply_patch`, `edit_file`,
  `write_file`, `apply_diff`, `bash`, `run_command`, `terminal`, `run_code`) обнуляет счётчик.
- Выбор — **пустая операция**, если агент уже на целевой модели: долгая сессия не дёргает модели
  без причины.

### Конфигурация

Панель пишет через редактор конфига профиля, поэтому строка в Cordis-патче профиля выглядит так:

```yaml
- insert:
    - id: model-autopilot
      name: dsh-model-autopilot
      config:
        enabled: true
        escalateAfterErrors: 2
        tiers:
          fast:
            provider: deepseek
            model: deepseek-chat
          coder:
            provider: deepseek
            model: deepseek-reasoner
          heavy:
            provider: ''
            model: ''
```

| Поле | Смысл |
| --- | --- |
| `enabled` | главный выключатель; `false` — плагин ничего не наблюдает |
| `escalateAfterErrors` | сколько подряд ошибок до `heavy`; `0` — без эскалации |
| `tiers.*.provider` / `tiers.*.model` | id провайдера и модели из «Настроек → Модели»; оба пустые — уровень пропущен |

## Данные и приватность

Панель общается с Host-половиной по аутентифицированному маршруту того же источника
(`/api/model-autopilot/state`, `/api/model-autopilot/settings`). Текст диалога, промпты и ключи
провайдеров не покидают машину: своего сетевого кода у плагина нет.

## Честные ограничения

Плагин маленький и намеренно простой. Чего он **не** умеет:

- **Классификатор — это набор ключевых слов.** Только русский и английский, без вызова модели и
  без контекста сессии. «Почини опечатку» и «почини падающий тест» попадут в одну категорию, а
  непривычные формулировки уйдут в `fast`.
- **Смена модели посреди сессии может обнулить prompt-кеш провайдера**, и следующий запрос будет
  дороже. Это цена маршрутизации: держите `fast` близким по цене к `coder`, чтобы переключений было
  меньше.
- **Эскалация наивная**: считается любой неудачный результат, включая `grep` без совпадений.
- **Плагин влияет на все сессии профиля**, включая суб-агентов, пока включён.
- **`heavy` — тупик по замыслу**: сам он не понижает уровень, это делает сброс счётчика на удачной
  правке или команде.
- **Политики на сессию пока нет** (в работе).

## Если что-то не работает

| Симптом | Причина |
| --- | --- |
| «Провайдеры не сообщают моделей» | провайдер ещё не настроен: **Настройки → Модели** |
| Настройки сохраняются, а модель не меняется | все уровни пустые или плагин выключен |
| Записи в боковой панели нет | bundle установлен, но веб-клиент не перезагружен |
| Сложные запросы уходят в `fast` | формулировка не совпала с эвристикой; временно поставьте одну модель и в `fast`, и в `coder` |

## Разработка

Ни сборки, ни бандлера, ни зависимостей — два ESM-файла:

| Файл | Роль |
| --- | --- |
| `index.js` | Host-половина: события, маршрутизация, два аутентифицированных маршрута, запись конфига |
| `client.js` | Веб-половина: иконка в `sidebar.panellist`, панель, локаль, стили |
| `cordis.patch.yml` | патч bundle, который вставляет строку, выключенную по умолчанию |
| `locale/*.json` | название и описание для каталога, en и ru |
| `verify.mjs` | офлайн-проверка обеих половин (подставной `ctx`, без браузера) |

```bash
npm test        # или: node verify.mjs
```

`verify.mjs` поднимает Host-половину на заглушке контекста и проверяет маршрутизацию, сохранение
настроек, оба Fetch-маршрута, регистрацию клиента, локали и одну отрисовку панели.
